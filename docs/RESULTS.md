## 8. seq 内核 v0（token 时序相关度，MVP）

> 内核第一版，范围按 2026-11-09 定的 MVP：**只做 token 化 + 时序相关性**，深度学习先不铺开。
> 内核工件（`tools/kernel/build_seq.py`）提供词表 / idf / token 间有序转移权（order=1 相邻、order=2 隔一，PPMI）；
> 外壳（`crates/sl-adapters/src/seq.rs`）把 BM25 基本分与「时序分」融合：
> `score = s_uni + λ_seq · Σ e(a,b)·(1+ln(c))`（详见 KERNEL.md §8）。

### 8.2 消融（scifact，λ=0.5 为默认；括号里是相对 bm25 的 ΔnDCG@10）

| 变体 | nDCG@10 | 读法 |
|---|---:|---|

| `seq` λ=0.05 | 0.6641 | — |
| `seq` λ=0.1 | 0.6655 | +0.0008（单次运行，不能读成增益） |
| `seq` λ=0.3 | 0.6599 | 开始变差 |
| `seq` λ=0.5（默认） | 0.6515 | −0.0132 |
| `seq` ordered=false | 0.6509 | 比有序还差 → 顺序本身有微弱信息 |
| `seq` orders=[1] | 0.6583 | 只用相邻阶比 [1,2] 好 → 隔一阶带来了噪声 |

| `seq` window=16 | 0.6470 | 窗口越大越差 → 距离越远越不该加分 |

### 8.3 怎么读（结论与边界）

1. **统计版时序分目前没有增益**：四个数据集上 λ=0.5 都比同口径 `bm25` 低；λ=0.1 在 scifact 上只高 +0.0008（单次运行，
   谈不上增益）。这与预期一致：PPMI 是「共现统计」，不是「学到的相关度先验」，它把大量弱相关邻接当成证据，
   在短文档/短查询上主要制造噪声。
2. **但结构与工具链已经成立**：工件格式、哈希审计、CPU 运行时、Python↔Rust 逐位对拍（见 8.4）、
   λ/窗口/阶数/有序性的消融开关全部就位——后续换「学习到的权重」只换工件，不动外壳与指标。
3. **消融给出的方向（供学习版参考）**：顺序（ordered）与近邻（order=1、窗口 ≤8）有微弱正信息；
   隔一阶与大窗口引入噪声。学习版应该只在这些有信息的边上学习权重，而不是全量 PPMI 边。
4. 证据强度：每格**单次运行**；延迟在同一台机器（有 GPU，但运行时强制 CPU）测得，rs 等外部对比不可与本章混读。

- 工件（`data/<name>/artifacts/seq-v0/`）登记在 run.json：`seq_graph / corpus_ppmi / runtime=cpu`，

## 9. M2-lite：学 2 个时序权重（kernel v1）—— 预注册口径作废，但测出关键分辨率

预注册与全部读数见 [`docs/PREREG-M2.md`](PREREG-M2.md)。这里只记结论。

### 9.1 结果

| 项 | 值 |
|---|---|
| 训练数据 | scifact train split：809 条查询 / 919 条正例（新增 `train_queries.jsonl` + `train_qrels.tsv`，**不进 manifest 指纹**） |
| 学习参数 | **2 个**（`a1`、`a2`；`λ` 与阶权重之间只有一个尺度自由度） |
| 预注册口径结果 | `a1 = a2 = 0`（边界解），代理损失 400 步不动，top-10 变化 **0%** |
| 按预注册纪律 | N4（非零性冒烟 ≥10%）**未过** ⇒ 该变体**作废**，不出「有效/无效」结论 |
| test | **未跑**：a=0 ⇒ `seq` 与 `bm25` 逐位相同（N1 已证），Δ 恒为 0 |

### 9.2 诊断：不是「特征没信号」，是「集成方式与代理饱和」

| 逐查询 AUC（正例 vs 同查询候选负例） | s_uni 0.972 | s1（order=1）**0.791** | s2（order=2）0.631 |
|---|---|---|---|

- `a=0` 处 `dL/da1 = +0.0046 > 0` ⇒ 非负约束下最优就在 0，不是优化没跑够；
- 分数未归一（均值 `|du|` = 27.9），pairwise logistic 饱和到 sigmoid ≈ 0 ⇒ 梯度近乎为 0；
- 归一化后权重能动了（探索性变体：best train ΔnDCG@10 = **+0.0006**），但仍远小于可判定阈值。

结论：**时序特征本身有信息（AUC 0.79），但以「加性 bonus 叠在 BM25 上」的方式在 2 参数下学不出增益**；
瓶颈在集成方式与测量分辨率，不在参数数量。

### 9.3 一个影响所有旧结论的校准：scifact test 只能分辨 0.0143

用同一轮配对结果（`results/scifact-20261109-181810-seq-fixed`）做 4000 次配对 bootstrap：

```text
300 条计分查询 → ΔnDCG@10 的 bootstrap SE = 0.00716
Δ_min = 2×SE = 0.0143
```

⇒ **scifact test 上只有 |Δ| ≥ 0.0143 才可判定**。因此 §8.2 消融表里的所有差异
（0.0008 / 0.005 / 0.013，包括「λ=0.5 比 bm25 差 0.0132」）**全部落在噪声带内**：
「λ 越大越差」「order=2 是噪声」「ordered 优于 unordered」这些方向性说法在 scifact 上**都还不成立**，
只能写「该口径下未测出差异」。§8.2 的表格保留为原始读数，但读法以本节为准。

> 这条校准来自 flowme 的 Δ_min 纪律（`docs/REFERENCE_NOTES.md` §2）：**没测出差异 ≠ 没有效果**。
> 后续所有小效应实验必须先看目标数据集的 Δ_min，再决定值不值得做。

## 10. M2b：以搜索缺失率为目标（精确网格，无代理损失）

完整记录见 [`docs/PREREG-M2b.md`](PREREG-M2b.md)。这里只记结论与它对路线的含义。

### 10.1 先把「缺失率」变成一等指标

`sl-core` 新增 `Metrics.hit`（`hit@k` = top-k 里至少命中一条相关文档的查询占比），报告里新增
「查询命中率 / 缺失率」表。它和 recall 的口径不同，不能混读：

| 场景 | recall@10 | hit@10 |
|---|---:|---:|
| 一条查询有 5 篇相关，只召回 1 篇 | 0.2 | **1**（没漏） |

`docs/STANDARD.md` §5 已补该定义，含「hit/miss 报 Δ 时必须给 Δ_min」的纪律。

### 10.2 scifact 上的缺失率现状（bm25，300 条计分查询）

| 指标 | 值 |
|---|---:|
| miss@10 | **19.67%**（59 条查询第一屏一条都没命中） |
| miss@100 | 10.33%（31 条） |
| 其中 11–100 名（重排可救） | **9.3%**（28 条） |
| 其中 top-100 完全没有相关（打分救不了） | **10.3%**（31 条） |
| 完美重排的 hit@10 上限 | 0.8967（现状 0.8033） |

### 10.3 结果：直接优化缺失率，仍然零增益

| 阶段 | 读数 |
|---|---|
| train 网格搜索（1402 点，含负值扩展 225 点） | 最优 `(a1=0, a2=0.2)`，hit@10 0.8140 → 0.8152，**只多命中 1 条查询** |
| test（只跑一次） | hit@10 **0.8033 → 0.8033（Δ=0.0000，0 条查询变化）**；hit@100 −0.0033 < Δ_min 0.0067 |

- 换目标（排序代理 → 业务缺失率）、换优化方式（梯度 → 精确穷举）、换样本（train 809 条）
  **都指向同一答案**：2 个加性时序权重对「能不能命中」没有作用。
- 原因：命中由**前 10 名边界**决定，而加性时序奖励对所有含查询词项的文档普遍加分，
  基本不改变候选相对次序——它不能把第 30 名推上前 10。

### 10.4 对路线的含义（重要）

「搜索缺失率」这个目标是对的，但它指向的**不是**时序权重，而是两个别的模块：

| 缺失类型 | 占比 | 需要的机制 | 属不属于当前内核 |
|---|---:|---|---|
| 首个相关在 11–100 名（重排可救） | 9.3% | 能区分近邻候选的信号（cross-encoder / query-doc 交互分 / 更强的学习表示） | ❌ 超出「2 个时序权重」 |
| top-100 完全无相关（词汇不匹配） | 10.3% | 查询扩展、同义/缩写归一、更好的表示 | ❌ 属于召回/表示层 |

⇒ MVP 阶段「token 化 + 时序相关性」这条内核路线到此有了明确边界：**它能做的是排序细分，
做不到救漏**。要继续降低缺失率，得进入重排或表示层——那已超出「内核只学时序特征」的范围，
需按 `docs/STANDARD.md` §8 重新排期。

## 11. 换 LLM tokenizer（`bm25-llm`）—— 单变量对照：**纯词法上更差**

动机：词级切分丢掉形态学（`monocyte` ≠ `monocytes`）。实测「硬漏」查询的相关文档词级覆盖率只有
0.323，而字符 3-gram 能到 0.604 ⇒ 子词信息确实存在。按「不自己造」的原则，直接用成熟 LLM 的 BPE。

### 11.1 设置

| 项 | 值 |
|---|---|
| tokenizer | Qwen2.5-0.5B `tokenizer.json`，BPE，151,665 词表，sha256 `c0382117…` |
| 对照组 | `bm25`（词级切分，`tokenize::bm25_terms`） |
| 唯一变量 | **tokenizer**；k1=1.5 / b=0.75 / 同分排序 / 过滤规则完全相同 |
| 数据 | scifact，同一指纹 `7bf0074d…`，k=100，warmup=3 |

### 11.2 结果

| 指标 | `bm25`（词级） | `bm25-llm`（BPE） | Δ |
|---|---:|---:|---:|
| nDCG@10 | **0.6647** | 0.6350 | −0.0297 |
| MRR@10 | **0.6328** | 0.6006 | −0.0322 |
| R@10 | **0.7849** | 0.7644 | −0.0205 |
| R@100 | 0.8892 | 0.8927 | +0.0035 |
| **miss@10** | **19.67%** | 22.33% | **+2.67pp（更差）** |
| miss@100 | 10.33% | 10.33% | 0 |
| 索引 ms | 186 | 1,613 | 8.7× |
| 查询 p50 ms | 0.21 | 0.44 | 2.1× |

配对 bootstrap（300 条计分查询）：`ΔnDCG@10 = +0.0297`，`SE = 0.0138`，**`Δ_min = 0.0277`**
⇒ 这个差距**刚刚超过可判定阈值**（不是噪声，但幅度不大）。

### 11.3 诊断：为什么更差，以及它救回了什么

- **token 数膨胀 1.46×**（词级 229/文档 → BPE 333/文档），BM25 的 `b` 与词频饱和在不同粒度上标定不同；
- **IDF 被摊薄**：BPE 拆出 `mon`、`ation`、`Ġthe` 这类高频子词，它们在几乎所有文档里出现，
  对排序几乎没有区分度；而 BM25 的全部威力来自「稀有精确词」。
- **但它是互补的**：`hit@10` 上 llm **救回 11 条** bm25 漏掉的查询，同时**弄丢 19 条**，净 −8。
  ⇒ 子词信号真实存在，只是被「高频子词摊薄 IDF」掩盖了。

### 11.4 结论与下一步

**「直接换 LLM tokenizer」这条路单独走不通**（至少在纯词法 BM25 上），但它证明了子词信息有价值。
两条可行的接法（都还没做）：

| 选项 | 思路 | 预期 |
|---|---|---|
| **A. 混合打分** | 词级 BM25 为主 + 子词 BM25 为辅（或只在词级零命中时用子词兜底） | 吃回那 11 条，同时不丢那 19 条 |
| B. 重新标定 b/k1 | BPE 文档更长 ⇒ b 可能需要下调 | 小幅，且要在 train 上调、test 上一次评 |
| C. 交给神经路径 | BPE 本来就是给模型用的：用它做 embedding / cross-encoder 的输入 | 超出当前「词法 + 时序」范围 |

**证据强度：单次运行，但 Δ 刚过 Δ_min**；延迟与索引差异是量级性的，不依赖统计。

## 12. 外壳重建 + OAC 主算法：等价性门通过，但有序约束**有害**

完整定义与复现命令见 [`docs/ALGORITHM.md`](ALGORITHM.md)。

### 12.1 做了什么

新建 `crates/sl-engine` 作为**检索外壳**（此前没有外壳，只有 5 份各自复制倒排的适配器实现）：

| 组件 | 内容 |
|---|---|
| `PositionalIndex` | 唯一一份位置索引（倒排位置表 + df/len/idf），**不认识 tokenizer**（token 以 u32 传入） |
| `BowScorer` | 词袋端点（BM25 数学），用于等价性门与消融对照 |
| `OacScorer` | 主算法「有序对齐覆盖」：最优有序对齐上的 BM25 逐项权重和 |
| `KernelGapTable` | 内核的唯一接口：gap（1 / 2 / 3–4 / 5–8 / >8）→ 权重 |

适配器 `bow` / `oac`；tokenizer 由 `SL_SHELL_TOKENIZER` 切换（word / qwen）。

### 12.2 等价性门（这是外壳可信的前提）

| 门 | 判据 | 结果 |
|---|---|---|
| **G1** | `bow` 与既有 `bm25` 逐查询一致 | ✅ **300/300 条，0 差异** |
| **G1'** | OAC `ordered=false` 与 `bm25` 逐位一致（BM25 是本算法的退化情形） | ✅ **300/300 条，0 差异** |

G1' 的意义：BM25 不再是"要被击败的对手"，而是本算法 `ordered=false` 时的特例——这让消融变成
"同一公式里关一个语义维度"，而不是"两套实现比大小"。

### 12.3 主算法实测与消融（scifact，k=100，Δ_min = 0.0143）

| 配置 | nDCG@10 | MRR@10 | 相对 BM25 |
|---|---:|---:|---:|
| `ordered=false`（= BM25） | **0.6647** | 0.6328 | 基准 |
| 有序 + 无折扣 | 0.5427 | 0.4992 | −0.1220 |
| 有序 + 衰减核 | 0.5569 | 0.5134 | −0.1078 |
| 有序 + window=4 | 0.5432 | 0.4971 | −0.1215 |
| 有序 + window=16 | 0.5632 | 0.5284 | −0.1015 |
| 有序 + max_skip=0 | 0.5118 | 0.4545 | −0.1529 |

所有差异都**远超 Δ_min**（0.0143），不是噪声。

### 12.4 结构性解释（比数字重要）

**有序约束在形式上是一个剪枝**：它只决定"哪些匹配可以同时计入"，永远**只能减少**可计入的证据，
不会增加任何新证据。查询有 8–10 个词、文档以不同顺序提及它们时，单调约束只能取一个子集，
分数必然低于"全部计入"。

要让顺序信息有用，它必须带来**加法**（相邻匹配额外加分）而不是**减法**。而"加性奖励"这条我们
已经单独测过（§8–§10）：train 上 1402 个网格点最多多命中 1 条查询，test 上 0 条变化。

⇒ 三条独立路径（加性奖励、train 上学权重、有序对齐剪枝）指向同一结论：
**`query token 在文档中的顺序/邻近` 这个信号，在 scifact 上不携带可提升排序的增量信息。**

### 12.5 成本

| 项 | `bow` | `oac` |
|---|---:|---:|
| 索引 ms | 175–186 | 181–187 |
| 查询 p50 ms | 0.21 | **7.1（≈33×）** |
| 查询 p95 ms | 0.26 | 16.8 |

OAC 慢在「每篇候选都要做一次对齐 DP」，当前未做候选裁剪。若继续这条路，必须先按廉价分取 top-N。

### 12.6 实现中修掉的两个真 bug（单测抓出）

1. **环形缓冲取模做位置校验**：窗口小于实际距离时会把远处位置错认成近处，产生虚假对齐转移；
   改为「(位置, 值) 显式校验 + 前缀最优」。
2. **无序端点概念写错**：最初仍要求查询下标递增（带着查询顺序），导致反序文档被系统性压低；
   真·无序端点应是每个查询词独立贡献（词袋），改后与 BM25 逐位一致。

### 12.7 边界

只在 scifact（英文短摘要）验证；中文短标题（qbqtc）、长文档（nq-sub）未测；只验证了这一族词法算法，
**未**验证学习到的稠密表示（那是另一个信号源）。结论是「该特征在该任务无增益」，不是「顺序信息普遍无用」。

## 13. 先验因子 v0：token → 关联 token（P0 零参数基线）

按 `docs/KERNEL.md` §0 的术语，内核的**输出**叫「先验因子」。这一节测第一种因子形态：
**查询 token → 关联 token + 置信度**（token 扩展），内核网络参数量 **0**（统计直接产出，
`network.arch = "none（P0：统计直接产出，零参数基线）"`）。

### 13.1 是什么

| 项 | 内容 |
|---|---|
| 扩展候选来源 | `seq-v0` 工件的 PPMI 边（order=1/2 有序共现） |
| 置信度 | 该源 token 最大出边权重归一，`conf ∈ (0,1]` |
| 因子规格 | `kind = token_confidence_list`，`shape = [n_query_tokens, top_k]`，scifact 上 48,126 条对 |
| 外壳消费方式 | 检索词 = 原词(权重 1.0) ∪ 扩展词(权重 `alpha × conf`) |
| 工件 | `data/scifact/artifacts/exp-ppmi-v0/`（manifest 里分列 `prior_factor` 与 `network`） |

### 13.2 固定 alpha 的效果：总体变差，但**硬漏被救回**

| 配置 | nDCG@10 | R@100 | hit@10 | 查询 p50 |
|---|---:|---:|---:|---:|
| BM25 基线（无扩展） | **0.6647** | 0.8892 | 0.8033 | 0.21 |
| alpha=0.1 | 0.6602 | 0.8859 | 0.8000 | 13.5 |
| alpha=0.3 | 0.6460 | **0.8976** | 0.8033 | 13.2 |
| alpha=0.5 | 0.6166 | 0.8942 | 0.7867 | 13.4 |

按基线分桶看"谁被救了、谁被弄丢"：

| alpha | 硬漏子集救回（/31） | 11–100 名救回（/28） | top-10 命中被弄丢（/241） |
|---|---:|---:|---:|
| 0.1 | 1 | 2 | 3 |
| 0.3 | **5** | **5** | 5 |
| 0.5 | 5 | 6 | 13 |

**这是整条线上第一次看到"目标失败被真正修好"**：硬漏 31 条里救回 5 条（16%），
11–100 名里救回 5 条。代价是 top-10 弄丢 5 条（救回来的名次更靠后，所以 nDCG 反而降）。

### 13.3 关键发现：扩展信号**依赖查询**，不能全局开

把每个查询在 4 个配置（base / 0.1 / 0.3 / 0.5）里取最优，得到**逐查询 oracle 上限**：

| 项 | hit@10 | nDCG@10 |
|---|---:|---:|
| BM25 基线 | 0.8033 | 0.6647 |
| 固定 alpha=0.3 | 0.8033 | 0.6460 |
| **逐查询 oracle** | **0.8267（+2.33pp）** | **0.6883（+2.36pp）** |

oracle 的配置选择分布：**base 272 条 / alpha=0.5 25 条 / alpha=0.3 3 条**。

也就是说：**只有约 9% 的查询适合扩展，其余 91% 扩展只会掉精度**。固定 alpha 必然两头不讨好。

### 13.4 结论与下一步

1. **先验因子的形态是对的**：token → 关联 token 确实能修"词汇不匹配"这一类漏，
   而之前的时序/位置方案从原理上就修不了。
2. **P0（零参数、全局 alpha）不足以兑现它**：净效果为负。
3. **但 oracle 上限 +2.36pp nDCG 超过了 `Δ_min = 1.43pp`** ⇒ 这个方向**可判定**，
   值得上 P1：把置信度变成**逐查询/逐 token 的可学习量**，用 ES 直接优化 harness 指标。
4. 成本注意：扩展让查询变长（词数 ×(1+k)），p50 从 0.21ms（bm25）涨到 13.2ms（bow+扩展）。
   P1 若上线必须先做候选裁剪。

> 证据强度：单次运行；但 oracle 上限与 Δ_min 的比较用的是同一批配对查询，结论方向可靠。

## 14. field 启发：字段结构有信号，per-token 因子形态无效

按 `docs/KERNEL.md` §4 的因子契约，内核产出 `token → [(字段, 出现率)]`（`kind = field`，
`tools/kernel/build_field.py`，scifact 上 20,269 token / 30,316 条证据，payload sha256
`eb140bbaaf14…`），外壳 `field-bm25` 用 `tf_eff = tf_full + beta · conf_title(t) · tf_title` 消费它。

### 14.1 先证明字段结构本身带信号（控制词重叠）

只统计 train qrels 里判定过的文档，并**限定正文已命中 query 词**，排掉「相关文档本来就更容易
包含查询词」这个混淆：

| 桶（限正文命中） | 标题命中率 |
|---|---:|
| 相关文档 | 0.9117 |
| 其他正文命中文档 | 0.5748 |

逐 query 比值中位数 1.458，91.1% 的 query 比值大于 1。标题命中确实携带 BM25 拿不到的信息。

### 14.2 train pool 内 heldout 评测（663 outer-train / 146 heldout，k=100，不读 test）

| 臂 | nDCG@10 | Δ nDCG（95% CI） | Δ_min(2×SE) | Δ Recall@100 |
|---|---:|---:|---:|---:|
| `bm25` | 0.66018 | — | — | — |
| `uniform β=1` | **0.67386** | +0.01368 [-0.00085, +0.02999] | 0.01582 | -0.00685 |
| `uniform β=2` | 0.67321 | +0.01303 [-0.00615, +0.03314] | 0.01972 | -0.00856 |
| `uniform β=5` | 0.67080 | +0.01062 [-0.01061, +0.03288] | 0.02265 | -0.00856 |
| `factor β=1` | 0.66039 | +0.00021 [0, +0.00063] | 0.00002 | 0 |
| `factor β=2` | 0.66017 | -0.00001 [-0.00067, +0.00063] | 0.00002 | 0 |
| `factor β=5` | 0.66038 | +0.00020 [-0.00046, +0.00105] | 0.00046 | -0.00685 |
| `cond β=1` | 0.66104 | +0.00086 [-0.00637, +0.00731] | — | -0.00685 |
| `cond β=2` | 0.66485 | +0.00467 [-0.00608, +0.01516] | — | -0.00685 |
| `cond β=5` | 0.66695 | +0.00677 [-0.00545, +0.01901] | — | -0.00685 |

`uniform` = 标题命中一律按 β 放大（不依赖因子）；`factor` = 按 `β · conf_title(t)` 放大，
`conf` 取 `df_title / N`（field-v0）；`cond` = 同一形态但 `conf` 改取条件比例
`df_title / Σdf`（field-v1，量级 0.22~0.28）。

### 14.3 结论

1. **字段加权本身有正向点估计但未过噪声带**：`uniform β=1` 的 Δ nDCG = +0.01368，
   低于 Δ_min = 0.01582。按本仓纪律只能写「该口径下未测出超过噪声带的增益」，
   不能说「字段加权有效」。三个 β 呈 β 越小越好的单调趋势。
2. **per-token 因子形态是主要瓶颈，但修好量纲也不够**：`factor`（`df_title/N`，中位数
   0.00019）乘 β 后仍是 0.001 量级，相对 `tf_full`（1~5）微不足道——即使 β=1000 也只能
   让第 4、5 名互换，CI 宽度仅 0.0006。换成量纲正确的条件比例（`cond`，0.22~0.28）后，
   Δ nDCG 从 +0.0002 抬到 +0.0068（β=5），证明**量纲是一部分原因**；但同样 β 下仍只有
   `uniform` 的约一半（+0.0068 vs +0.0137）。
   机制推断：`conf` 的分布只有 0.22~0.28 这么窄，per-token 区分本身就接近噪声，
   而 `uniform` 给每个标题命中一个满额 boost，没有把重要词压下去。
3. **诊断信号与因子形态是两个量**：§14.1 证明有信号的是「**该文档的标题是否命中该 query 词**」
   （文档级结构事实），而因子给的是「**该 token 在语料里有多标题化**」（全局统计）。
   后者被 BM25 的 idf 基本覆盖，前者才是有效信息。

### 14.4 对因子设计的含义

`uniform` 不依赖任何因子就拿到了最大的字段收益（+0.01368，仍是本组最好的点估计）；
两套 per-token 因子形态都没超过它。结论：**field 启发在 scifact 上不需要内核产出 per-token 因子**——
只要外壳能建分字段索引，一个全局 β 就是全部有效信息，per-token 区分反而稀释了 boost。

若仍要走因子路线，需要证明因子带来 `uniform` 拿不到的增益，而不是复述「哪些词常在标题出现」。
候选方向：`idf_title(t)` / `idf_full(t)` 这类量纲正确且 BM25 未覆盖的字段证据；
但在 scifact 这种小语料上，先验仍是 `uniform` 更可能胜出。

**注意证据强度**：所有臂的 Δ nDCG 都未超过各自的 Δ_min(2×SE)，包括最好的 `uniform β=1`
（+0.01368 < 0.01582）。因此本节能支撑的结论只有「未测出超过噪声带的增益」，
以及「per-token 因子显著弱于 uniform 这个相对比较」（同一批配对查询、同一外壳，相对结论比绝对增益可信）。

复现：

```bash

  field-eval --dataset scifact --k 100 --output results/field-eval.json
```

## 15. concept 启发：内核**学出**的概念归并，与字段加权叠加后越过噪声带

这是本仓库第一次有配置在 heldout 上超过 `Δ_min`。核心变化不是换算法，而是**先验因子的来源
换成了学习**：概念归并由一个 9 参数的内核谓词决定，权重在 outer-train 上优化 nDCG@10 得到，
**没有任何手写后缀规则**。

### 15.1 内核是什么

| 项 | 内容 |
|---|---|
| 先验因子 | `token → 规范形式`（`kind = concept`，3617 个 token 归并到 2514 个概念） |
| 内核网络 | `merge(t,u) = σ(w·x(t,u) + b) ≥ 0.5`，输入是候选对的**语料统计特征** |
| 参数量 | **9**（8 个特征权重 + 截距） |
| 候选对空间 | `t` 是 `u` 的前缀且 `len(t) ≥ 3`（结构约束，语言无关；不含后缀表） |
| 特征 | `p_t_given_u`、`p_u_given_t`、`jaccard`、`log_df_ratio`、`len_ratio`、`extra_chars`、`tf_cosine`、`ppmi` |
| 学到的权重 | `[2.0, 0.5, 0.5, 0, 0, 0, 0, 0]`，截距 `−0.5`（其余 5 个特征被压到 0） |
| 目标 | outer-train（663 条）上的 nDCG@10，坐标搜索（非代理损失） |
| 工件 | `data/scifact/artifacts/concept-v0/`（`concepts.json` 112,191 B，sha256 `e5d3f109baf8f3dd…`） |

外壳 `concept-bm25` 的用法是**索引期归并**：文档 token 与查询 token 都先映射到规范形式再进
`PositionalIndex`，其余（idf 定义、k1/b、同分排序）与 `bm25` 完全相同。映射为空时与 `bm25`
逐查询一致（`concept_mode_with_empty_map_matches_bm25` 守着）。

### 15.2 先被证伪的三个方向（附带读数，避免以后重做）

在实现外壳之前，先用一份与 Rust 口径逐位一致的 Python 诊断脚本（在 heldout 上复现出
`bm25 0.66018` / `uniform β=1 +0.01368`，证明它与权威 harness 同口径）扫掉了三个候选：

| 方向 | 因子含义 | outer-train Δ nDCG | heldout Δ nDCG | 判定 |
|---|---|---:|---:|---|
| `field_idf` | 标题命中用 `idf_title`，正文用 `idf_full` | −0.0361 | −0.0115 | 两套划分都大幅为负 |
| `idf_lift` | 词项权重 ∝ `idf_title/idf_full` | −0.0748 | −0.0684 | 远超噪声带，明确有害 |
| `saliency` | 词项权重 ∝ 其 tf 分布集中度 | −0.0664 | −0.0594 | 同上 |

三者都是「给同一个 BM25 乘一个 per-token 系数」，方向与 §14 的结论一致：**per-token
全局统计对词项加权没有正信息**。这也解释了为什么必须换到「改变词项身份」的归并，而不是继续调权重。

### 15.4 结论与它的边界

1. **单独的 concept 与单独的 uniform 都过不了噪声带**（heldout 上各为 +0.01872 / +0.01368，

   这说明两条信号**互补**：概念归并改「词项身份」，字段加权改「同一词项的 tf 贡献」，并不重复。
2. **outer-train 上 6 个臂里 4 个越过 2SE**，方向与 heldout 一致，这是本仓目前最强的证据形态
   （两套划分同向、其中一套越过噪声带）。但 outer-train 同时是训练集，
   它上面「越过 2SE」不能当独立证据——只说明效果不是只在 146 条上偶然出现。
3. **不能说成「concept 有效」的定论**：只用了**一个** heldout 划分，6 个臂未做多重比较校正，
   heldout 上恰好 2 个越过——这符合「真有效应」也符合「6 次里挑中 2 次」。要下定论得换数据集复核
   （下一步），或在同一划分上做置换检验。
4. **成本**：`concept` 让 p50 从 207µs 涨到 384µs（归并查表），叠加字段加权后 837µs（两套索引）。
   仍是亚毫秒级，但比 `bm25` 慢 4 倍，报告里必须与效果分列。
5. **范围**：候选对生成器按「前缀」找形态变体，只对**后缀屈折**的语言成立（英文/德文等）。
   中文没有这种形态关系，这个候选空间在 qbqtc 上没有意义——**未在中文/长文档上测**，
   不能把本节结论推广到其他数据集。

## 17. 手动检索对比：从逐查询读到失败机制

聚合指标只说「平均好了多少」，这一节回答「到底好在哪、坏在哪」。

### 17.1 heldout 逐查询对比（`bm25` vs `concept`）

**收益最大的形态**：查询里的命名实体/词根与文档形态不同，归并后命中。

| qid | 查询片段 | 现象 |
|---|---|---|
| 1188 | `activator E2Fs ... terminally differentiated` | bm25 前 10 全不中（nDCG 0），归并 `e2fs→e2f` 后首位命中，nDCG 1.0 |
| 1346 | `... mutations in epidermal growth factor ...` | 正确文档从第 2 位升到第 1 位 |
| 1165 | `... hypomethylated ... H3K36 histone` | 首次进入前 10（第 4 位） |

**变差的形态**：`qid=1236`（`adipocytes` 相关）在 bm25 下第 9 位命中，归并后掉出前 10（nDCG 0.301 → 0）。

### 17.2 机制一：归并会稀释 idf（已验证，但不是主要瓶颈）

归并让词项 df 变大 ⇒ idf 变小；而 BM25 的 tf 饱和意味着「合并 tf」的收益远小于「idf 损失」。
针对这一点做了逐项对照（scifact，outer-train / heldout 的 Δ nDCG）：

| idf 取法 | outer Δ | heldout Δ | 判定 |
|---|---:|---:|---|
| 归并后 df（当前） | +0.02025 | +0.01872 | 基准 |
| 只用规范形式自身的 df | +0.02115 | +0.01830 | 两套划分互相抵消，无增益 |
| 组内最大 idf（最稀有成员） | −0.05219 | −0.07568 | 明确有害 |
| 组内平均 idf | −0.01776 | −0.02620 | 明确有害 |

⇒ **idf 稀释真实存在，但换 idf 口径不能拿回收益**：把最稀有词的高 idf 强加给整个概念组，
等于让常见形态继承了稀有形态的权重，排序被更严重地拉偏。

### 17.3 机制二：候选空间的两处缺陷（已修，可判定）

审 v0 的 3617 条归并，发现两处**具体的语义缺陷**（不是调参问题）：

| 缺陷 | 证据 | 后果 |
|---|---|---|
| 高频前缀污染 | 127 个内容词被并进 8 个停用词：`therapy→the`、`therapeutic→the`、`formation→for`、`interval→into` | 内容词退化成停用词，idf 与区分度全丢 |
| y→ies 型复数全漏 | 语料 228 对 `activities/activity` 型单复数，严格前缀规则只覆盖 **6** 对（`antibody` 不是 `antibodies` 的前缀） | 最常见的英语复数形态基本没被归并 |

原因：v0 的候选空间是「`t` 是 `u` 的严格前缀」，它同时做了两件错事——
放进 `the`/`therapies` 这种毫无形态关系的对，又漏掉词干发生变化的 `-y→-ies`。

**修法（v1）**：候选对改成「共享前缀至少覆盖较长词的 70%」。这仍是**结构约束**，
判定依然由学到的权重决定（不引入任何后缀表）。效果：

| 项 | v0 | v1 |
|---|---:|---:|
| 归并 token 数 | 3617 | 8506 |
| y→ies 覆盖 | 6/228 | **145/228** |
| 被并进停用词的内容词 | 127 | **1** |

### 17.4 数据集外的手工查询（无 qrels，只作机制核对，不作指标结论）

用 8 条**不在数据集里**的自造查询（形态刻意与摘要写法不同）在 scifact 语料上对比。
- 有归并命中的查询：`E2Fs controlling ...`（`e2fs→e2f`、`cell→cells`、`tissues→tissue`）
  首位从 `41710132` 换成 `4394817`（E2F 主题论文）；`hypomethylation of histone H3K36`
  （`h3k36→h3k36me3`）首位换成 ZMYND11/H3.3K36me3 论文——方向符合预期。
- **无归并命中的查询，排序也会被改动**（`CRISPR`、`ATP` 的 2/3 名互换）。原因是归并改变了
  文档侧词项 df/idf，**影响会泄漏到与形态无关的查询**。这是「概念归并」的固有副作用：
  它不是局部操作。这条在 `concept` 与 `bm25` 的差异里占相当比重，也是它只「刚好」越过噪声带的原因之一。

> 这一节没有 qrels，不能写成效果结论。它的用途是：确认归并**确实按预期触发**，
> 并找出后面两节的两个机制缺陷。

## 18. 优化点逐项判定（只保留越过噪声带的）

对一个「内核产出因子、外壳消费」的系统，可动的旋钮分三层：**因子内容**（候选空间/判定）、
**因子消费方式**（idf 口径/软归并/β）、**训练过程**（搜索算法/目标/划分）。
逐个做成单变量对照，判据统一是「heldout 上 |Δ nDCG@10| ≥ Δ_min(2×SE)」，
并要求 outer-train 与 heldout 方向一致。

| # | 旋钮 | 变更 | outer Δ | heldout Δ | Δ_min | 判定 |
|---:|---|---|---:|---:|---:|---|
| 1 | idf 口径 | 规范形式自身 df | +0.02115 | +0.01830 | 0.02142 | ❌ 两套划分互相抵消 |
| 2 | idf 口径 | 组内最大 / 平均 idf | −0.052 / −0.018 | −0.076 / −0.026 | — | ❌ 明确有害 |
| 3 | 消费方式 | 软归并 λ=0.75 / 0.5 / 0.25 | +0.0200 / +0.0169 / +0.0114 | +0.0205 / +0.0202 / +0.0192 | 0.0216+ | ❌ 与 λ=1 齐平或更差 |
| 4 | 归一化 | 禁止并进 df>1000 的 token | +0.02305 | +0.02000 | 0.02039 | ❌ 点估计略好，未过带 |
| 5 | 训练过程 | 多起点随机搜索 + 局部细化 | **+0.02143** | **+0.01589** | 0.02466 | ❌ 训练集变好、heldout 变差 = 过拟合 |
| 6 | 候选空间 | 严格前缀 → 共享前缀 ≥70%（v1） | +0.02759 | **+0.02487** | 0.02475 | ✅ **越过** |

### 18.1 v1 在权威 harness 上的读数（scifact heldout，146 条）

| 臂 | nDCG@10 | Δ nDCG | Δ_min(2×SE) | 95% CI | 是否越过 |
|---|---:|---:|---:|---|---|
| `bm25` | 0.66018 | — | — | — | — |
| `concept`（v1） | 0.68505 | +0.02487 | 0.02475 | [+0.00107, +0.05054] | ✅ |
| `concept β=1`（v1） | **0.69568** | **+0.03549** | 0.02796 | [+0.00892, +0.06433] | ✅ |
| `concept β=2`（v1） | 0.69368 | +0.03349 | 0.02832 | [+0.00698, +0.06231] | ✅ |
| `concept β=5`（v1） | 0.69172 | +0.03154 | 0.02913 | [+0.00410, +0.06109] | ✅ |
| `uniform β=1` | 0.67386 | +0.01368 | 0.01582 | [−0.00085, +0.02999] | ❌ |
| `uniform β=2` | 0.67321 | +0.01303 | 0.01972 | [−0.00615, +0.03314] | ❌ |

对照 v0（同一 heldout）：`concept` +0.01872（未过带）→ v1 +0.02487（过带）；
`concept β=1` +0.02770 → +0.03549。v1 相对 v0 的直接配对差是 **+0.00615（2SE 0.02800，噪声带内）**——
**所以「v1 比 v0 好」这一步本身没有被证明**，能说的只是 v1 自己的绝对增益越过了噪声带。

### 18.2 必须一起报告的负面结果

**同一个 β 下，训练出的概念因子没有跑赢「白给的 uniform 权重」。**

| 数据集 | 对比 | Δ | 2SE | 判定 |
|---|---|---:|---:|---|
| scifact heldout（v1） | `concept β=1` − `uniform β=1` | +0.02182 | 0.02461 | 噪声带内 |
| scifact heldout（v1） | `concept β=2` − `uniform β=2` | +0.02047 | 0.02403 | 噪声带内 |
| arguana test（v0） | `concept β=1` − `uniform β=1` | −0.0040 | 无区间 | 点估计为负 |
| arguana test（v0） | `concept β=2` − `uniform β=2` | −0.0046 | 无区间 | 点估计为负 |

⇒ 跨两个数据集、四种 β 的组合，**没有一次能判定「概念因子优于 uniform」**。
scifact 上点估计为正但不过带，arguana 上点估计为负。这与 §14.4 对 field 因子的结论同构：
**可迁移的是「β 加权」这个结构，不是这个因子的内容。**

### 18.3 结论

1. **能判定的一件事**：v1（共享前缀候选空间 + 重训）在 scifact heldout 上把 nDCG@10 从 0.66018
   抬到 0.69568（+0.03549，越过 Δ_min），且 outer-train 与 heldout 同向。
2. **不能判定的一件事**：「概念因子本身有价值」。因为它跑不赢 uniform 权重（§18.2），
   而 uniform 权重不需要内核、不需要工件、不需要训练。
3. **多次比较的代价必须说清**：本节试了 6 类旋钮、十余个配置，其中**只有候选空间这一项
   （#6）越过噪声带**，其余 5 项全部落在带内或不通过方向一致性检查。
   注意「越过带」不是 v1 独有的：§15.3 里 v0 的 `concept β=1/β=2` 也已经越过
   （+0.02770 / +0.03285）。v1 相对 v0 的**直接配对差是 +0.00615（2SE 0.028），没有过带**，
   所以「v1 的候选规则更好」这一步本身并未被证明。
   在一个 146 条查询的划分上做这种规模的搜索，**「恰好有一个过关」本身就会发生**——
   要把它变成结论，下一步必须换数据集复核（arguana 上 v1 也需要重做一次预注册读数）。
4. **已证伪、不要再走的路**（都是明确的负结果，不是「没测出」）：
   per-token 权重缩放（§15.2 三个方向全部大幅为负）、换 idf 口径、软归并、多起点搜索、
   禁止并进高频词。

## 19. 词性（语法）先验因子：受控负结果

§15–§18 的因子都是「语料统计直接算出来的」（df、标题率、前缀归并）。这一节试点第四类：
**语法/结构类**——一个 token 的**词性**（形容词 / 介词 / 动词 …），明确只要结构关系，不要语义
（不是「褒义/贬义」）。

### 19.1 为什么这次值得单独试（与 §15.2 的失败不重复）

被证伪的三个方向（`field_idf` / `idf_lift` / `saliency`）有一个共同点：**全是 `df` 的单调变换**，
而 BM25 的 idf 已经覆盖了 df。词性不是 df 的函数——高频名词与高频介词可以有相同 df、
完全不同的语法角色，这是第一个「原理上 BM25 看不到」的 per-token 信号。

### 19.2 语料：gold 词性标注，且从未接触 scifact

| 来源 | 领域 | 规模 | 许可 | 版本（锁 commit） |
|---|---|---|---|---|
| [CRAFT](https://github.com/lhunter-lab/CRAFT) | PubMed Central 开放获取**生物医学**全文 | 97 篇 / 639,475 token / 22,332 词形 | **CC BY 3.0**（许可文件随仓库分发） | `67ddf409` |
| [UD English-EWT](https://github.com/UniversalDependencies/UD_English-EWT) | 通用英文网络文本 | 16,622 句 / 251,491 token | **CC BY-SA 4.0**（官方页与 `LICENSE.txt` 一致） | `491be069` |

**领域匹配是关键**：scifact 是 MEDLINE 风格摘要，CRAFT 就是 PMC 全文，词形与句法都对得上。
抓取脚本 `tools/kernel/fetch_grammar_corpora.py`（锁 commit、带断点续传、写 `provenance.json`）。

**污染声明**：两者都没有接触过 scifact；词性标注不携带主题信息，因此与 embedding 类因子相比
泄漏风险天然更低。`contamination` 可如实写「无」。

**未采用**：GENIA（MEDLINE 摘要，领域最匹配）——其站点已迁到 Google Workspace 并需要登录，
**无法公开抓取**；GUM 许可带 NC（非商业），未用。

### 19.3 前置检查：覆盖率（先算这个，避免白建外壳）

| 来源 | scifact 词形覆盖 | **scifact token 次覆盖** |
|---|---:|---:|
| CRAFT | 35.1% | **91.0%** |
| UD EWT(train) | 20.4% | 75.1% |
| 并集（实际使用） | 41.9% | **92.9%** |

词形覆盖只有 41.9%，但**按 df 加权（token 次）覆盖 92.9%**：未被覆盖的词形几乎都是
`001` / `015` 这类编号，对排序没有权重。抽查的标签分布符合语言直觉：

```text
the → DET 1.00     of → ADP 1.00      cells → NOUN 1.00     human → ADJ 0.98
increases → VERB 0.71 / NOUN 0.29     increase → NOUN 0.80 / VERB 0.20
significantly → ADV 1.00              activation → NOUN 1.00
```

这与 §19.6 记录的上一版（无监督聚类）产物完全不同——那一版聚出的类是「纯数字」「基因名」，
不是语法类。

### 19.4 对照设计：上一版为什么作废，这一版怎么修

上一版（`tools/kernel/diagnose_grammar.py`，无监督 16 聚类 + 每类一个 λ）的读数是
`grammar +0.02516`、`df_bucket +0.01028`，但**`random` 臂逐位复现了 `grammar` 的 +0.02516**。
按当时预注册的决策规则 #0，整次读数作废：它证明被测量的不是语法类，而是「在任意 16 分箱上
拟合 16 个自由标量」这件事本身。

**修法**：零假设对照从「纯随机打乱」换成 **`df_strat_perm`——在 log df 的每一层内部置换**。
这样每个类别的**规模与 df 结构都被保留**，唯一变化的是「哪个 token 归到哪个类」。
纯随机之所以能复现增益，恰恰因为它破坏了 df 结构；分层置换不会。

三条臂的唯一差别就是「词 → 类」的对应表：

| 臂 | 类别来源 | 参数量 |
|---|---|---|
| `grammar_pos` | 真实 UPOS 分布（17 类） | 17 个 λ |
| `df_bucket` | log df 等频 17 桶 | 17 个 λ |
| `df_strat_perm` | 真实 UPOS 分布，但在 40 个 df 层内置换 | 17 个 λ |

打分：`w(t) = Σ_k p(k|t)·λ_k`；λ 全 1 时**逐位等于** `bm25`（等价性门，由脚本内
`baseline 0.66018` 断言守住）。λ 只在 outer-train（663 条）上拟合，heldout（146 条）只做判决。

### 19.5 读数（scifact，heldout，k=100）

| 臂 | outer nDCG@10 | heldout nDCG@10 | Δ vs bm25 | Δ_min(2×SE) | 95% CI | 判定 |
|---|---:|---:|---:|---:|---|---|
| `bm25` | 0.67232 | 0.66018 | — | — | — | — |
| **`grammar_pos`** | 0.68059 | 0.66000 | **−0.00018** | 0.01000 | [−0.01007, +0.01013] | 噪声带内 |
| `df_bucket` | 0.67682 | 0.66732 | +0.00714 | 0.02213 | [−0.01420, +0.02998] | 噪声带内 |
| `df_strat_perm` | 0.68456 | 0.67523 | +0.01505 | 0.02245 | [−0.00692, +0.03713] | 噪声带内 |

核心对比（两个臂的直接配对差）：

```text
grammar_pos − df_strat_perm = −0.01523   2SE = 0.02501   95% CI [−0.03993, +0.00929]
```

**真实的词性标签，点估计上还不如「保留 df 结构的随机标签」。**

学到的 λ 有一个可解释的形状（放大 DET 2.0、NUM 1.5，压 ADP/AUX/PRON/CCONJ/PART 0.5，
NOUN 1.0、VERB 0.75），也就是「抬限定词、压功能词」——但这套权重在 heldout 上换不到任何收益。

**干预非零性冒烟（R29）**：`grammar_pos` 让 heldout **146/146 = 100%** 的查询 top-10 改变。
远超 10% 门槛 ⇒ 这不是「改了但没生效」：因子确实在大范围重排，只是净收益为零。

### 19.6 结论与边界

1. **受控负结果**：在「每类一个乘子」这种外壳用法下，词性因子对 nDCG@10 的可测贡献为零，
   且不如同等 df 结构的置换对照。增益（+0.015）可被「17 个自由标量的分箱重加权」完整解释。
2. **上一版作废、这一版有效**：上一版测的不是语法（随机对照复现了增益）；这一版测的就是语法，
   结论是零。两件事必须分开写，不能合并成「语法因子无效」（上一版根本没测到它）。
3. **必须连同代理精度一起读（见 §22）**：本节用的类别来自**词形级查表**
   （`token → argmax P(UPOS)`），在留出集上准确率约 **89–95%**，且**原理上无法区分同一个词
   在不同句法位置的词性**。因此本节能支撑的说法是「**用这个精度的词形级代理，未测出增益**」，
   不能上升为「词性没有用」。
4. **只证伪了一种用法**。本节测的是 `w(t) = Σ_k p(k|t)·λ_k`（类别级乘子）。
   以下用法**未被检验**，不能用本节结论否定：
   - 用词性做**结构匹配**（如要求 query 的「形容词+名词」在文档里相邻出现）；
   - 用词性做**查询路由**（有动词的查询走不同策略）；
   - 用词性做**否定/谓词门控**。
4. **为什么这一类特别容易出「假阳性」**：任何 `df` 保序的 K 分箱 + K 个自由乘子，都能在
   146 条查询上凑出 +0.01～+0.02 的 nDCG。这给 §15–§18 也提了个醒：那些因子的增益里，
   有多少来自因子内容、多少来自「自由度本身」？`concept`（§18）**没有**做过等价对照——
   它不拟合 per-class 乘子，缺的是另一条：「等规模的随机归并，能不能也拿到 +0.02487」。
   那是 §18 结论仍然缺的一环，本节没有回答它。
5. **语料侧结论（可复用的基础设施）**：CRAFT 是本仓能找到的、与 scifact 同域且许可清晰的
   gold 词性语料；按 df 加权覆盖 91%。词性因子若要在别的用法上重试，这部分不用重做。

复现：

```bash
cd tools/kernel
uv run python fetch_grammar_corpora.py     # 下载 CRAFT + UD EWT（锁 commit，写 provenance）
uv run python diagnose_pos.py              # 覆盖率 + 三臂受控实测
```

> 证据强度：单数据集（scifact）、单 heldout 划分、λ 在 outer-train 上拟合。
> 负结果比正结果更不容易被噪声造假——这里 `grammar_pos` 的 Δ 是 −0.00018，且显著低于置换对照，
> 所以「没测出增益」这一条是稳的；「语法在所有用法下无用」**不是**本节结论。

## 20. `concept` 的等价对照：真实归并通过了检验

§19 的词性实验暴露了一个方法论缺口：**任何在 df 结构上做分组、再配若干自由度的操作，
都可能在小划分上凑出 +0.01～+0.02**。而 §18 里 `concept-v1` 是六个旋钮中唯一越过噪声带的
（+0.02487），却从未做过同类对照。本节补上。

### 20.1 对照设计：保留结构，只打乱「谁和谁同组」

真实归并的全部结构特征都保留，只把「哪个 token 落到哪个组」随机化：

- 被归并的 token 集合不变（13,080 个 token，来自 8,506 条归并 + 4,574 个规范形式）；
- 组大小分布不变（2..20，共 4,574 组）；
- 规范形式仍取**组内 df 最大者**（与真实规则一致）。

两个零假设：
- `shuffle`：随机重新分组，20 个 seed ⇒ 得到零分布；
- `df_adjacent`：按 df 排序后取连续块分组（比随机更苛刻：df 相邻的词未必是词形变体）。

### 20.2 读数（scifact，k=100）

| 臂 | outer Δ | heldout Δ |
|---|---:|---:|
| **真实归并（`concept-v1`）** | **+0.02759** | **+0.02487** |
| 随机归并（20 seed 均值） | −0.00967 | **−0.01501** |
| 随机归并区间 | [−0.01604, −0.00259] | **[−0.02812, −0.00502]** |
| 按 df 相邻分组 | −0.05193 | −0.06272 |

随机归并的 heldout 零分布：均值 **−0.01501**，SE 0.00155，95% [−0.02761, −0.00566]。
真实值 `+0.02487` **超出零分布上界**（分位 100%），与零分布均值相差 **+0.03988**。

### 20.3 结论与它不能说明的事

1. **机制是特定的**：不是「随便怎么分组都能涨」，恰恰相反——**任意分组都显著变差**
   （−0.015 到 −0.063）。真实归并（把 `cell`/`cells`、`antibody`/`antibodies` 这类形态变体
   合到一起）是唯一为正的那种分组。这一条对 §18 的结论是**加强**。
2. **为什么随机归并有害**：它会把毫不相干的词合并（比如把高频停用词和生僻术语并成一项），
   使 df/idf 严重失真；而形态变体本身分布高度相似，合并后 idf 变化很小，只增加命中。
3. **不能说明的事**：零分布整体为负，所以「真实值高于零分布」这个判据**很容易满足**，
   它检验的是**特异性**，不是显著性。相对 `bm25` 的效应量仍然是 `+0.02487 vs Δ_min 0.02475`
   ——依旧只是勉强越过，这一条没有变。

复现：`cd tools/kernel && uv run python null_concept.py --seeds 20`

> 证据强度：单数据集、单 heldout 划分；零分布 20 个 seed（同一批配对查询）。
> 这一节的作用是把 §18 从「一个过带的点估计」升级为「一个过带、且机制经过特异性检验的点估计」。

## 21. 词性的第二种用法：结构匹配（同样为零）

§19 只证伪了「每类一个乘子」。词性还有一类用法未被检验：**结构匹配**——
不改变词项权重，而是用词性筛出「构成短语」的查询相邻对，对它们在文档里相邻出现给奖励。

假设：`seq` / `oac`（§8 / §12）之所以有害，是因为对**所有**查询相邻对都给奖励，
其中大量是「名词 + 介词」这类跨短语的噪声对；若只用词性筛出 ADJ+NOUN、NOUN+NOUN 这类
真正的短语，相邻性奖励也许能变成正信号。

### 21.1 设置

| 项 | 值 |
|---|---|
| 查询侧 | 只保留内容词（ADJ/ADV/NOUN/PROPN/VERB/NUM）的序列，取相邻对 |
| 短语模式 | ADJ+NOUN、ADJ+PROPN、ADJ+ADJ、NOUN+NOUN、PROPN+NOUN、NOUN+PROPN、VERB+NOUN、ADV+ADJ、ADV+VERB、NUM+NOUN |
| 文档侧 | 两词在同一文档内最小距离 ≤ 5，奖励 `γ·1/(1+gap)` |
| γ | 在 outer-train 上扫 {0.2, 0.5, 1.0, 2.0} |
| 平均触发 | 每查询短语对 **4.62** 个 / 全部相邻对 7.40 个 |

三条臂的唯一差别是「选哪些查询对」，另配 `random_subset`（从同一查询的相邻对里
**随机抽同样数量**）控制「加了多少个奖励」这个混杂因素。

### 21.2 读数（scifact heldout，k=100）

| 臂 | 最优 γ | outer | heldout | Δ vs bm25 | Δ_min(2×SE) | 判定 |
|---|---:|---:|---:|---:|---:|---|
| `bm25` | — | 0.67232 | 0.66018 | — | — | — |
| `pos_phrase` | 0.2 | 0.67271 | 0.66029 | +0.00011 | 0.00066 | 噪声带内 |
| `all_pairs`（= §8 的 seq 族） | 2.0 | 0.67337 | 0.66070 | +0.00052 | 0.00439 | 噪声带内 |
| `random_subset` | 2.0 | 0.67289 | 0.66284 | +0.00266 | 0.00720 | 噪声带内 |

核心对照：

```text
pos_phrase − random_subset = −0.00255   2SE = 0.00717   95% CI [−0.01060, +0.00269]
```

**按词性挑出来的短语对，点估计上不如随机挑同样数量的对。**

### 21.3 结论

1. **结构匹配这条用法在这个代理下也是零**：`pos_phrase` 的 Δ 是 +0.00011，完全在噪声里；
   而且「选得对不对」没有差别（−0.00255，噪声带内）。词性在这里既没带来收益，
   也没带来它预期的「过滤掉跨短语噪声」的好处。
2. **`all_pairs` 这次只有 +0.00052，与 §8 的 −0.0132 不矛盾**：§8 用的是 PPMI 边权且
   对所有相邻对（含功能词）加分，本节只用内容词、奖励按距离衰减、且 γ 在外层调过。
   两者都说明同一件事：加性相邻性奖励在这个任务上没有正信号。
3. **词性的两条用法在本仓都试完了**：乘子（§19）与结构匹配（本节），都是零。
   但两节用的都是**词形级查表**（§22 测得准确率约 89–95%），而本节恰恰在机制最该生效的
   地方最弱：`increase`/`increases` 这类 NOUN/VERB 歧义词占 scifact token 次的 13.3%，
   词形级 argmax 用不上它们的逐次信息。**所以「语法因子不进外壳」这个决定只对当前代理成立。**

复现：`cd tools/kernel && uv run python pos_phrase.py`

> 证据强度：单数据集、单 heldout；γ 在 outer-train 上选（4 个值），故存在轻微的选择空间；
> 但 `pos_phrase` 与 `random_subset` 的差为负，说明即便有选择偏差也帮不上它。

## 22. 先验标签本身准不准：词性代理的质量评估（验收未通过）

§19 与 §21 直接拿词性去测排名，**却没有先验证标签本身**。这一节补那一步。
结论先说：**验收门槛未通过，因此逐次词性的检索实验没有运行。**

### 22.1 两类工具，两种精度

| 工具 | 建法 | EWT test（跨体裁） | CRAFT 留出折（域内） |
|---|---|---:|---:|
| 词形级查表（§19/§21 用的） | `token → argmax P(UPOS)` | 89.47% | 95.20%（5 折均值） |
| 上下文标注器（本节新建） | 平均感知机，窗口词 + 前后缀 + 形状 + 前一个标签 | **91.91%** | **96.70%** |
| 同上，仅用 CRAFT 训练 | — | 64.91% | 96.70% |

- 词形级查表的 EWT 数字是「EWT train 建表 → EWT dev/test 测」；CRAFT 数字是 5 折交叉。
- 上下文标注器（`tools/kernel/train_pos_tagger.py`，纯 numpy 平均感知机，216 万权重）：
  4 个 epoch，快照平均；EWT 数字是「EWT train 训练 → EWT test 测」，CRAFT 数字是「4 折训练 → 1 折测」。

**第三个数字是本节最重要的发现**：`CRAFT 单域 → EWT test` 只有 **64.91%**。
标签高度依赖语料，跨域会崩。而 scifact 是生物医学摘要、与 CRAFT 同域，所以
**「CRAFT 域内 96.70%」是唯一贴近 scifact 的估计，但 scifact 没有 gold，无法直接验证**。

### 22.2 验收门槛（事后未下调）

| 门槛 | 要求 | 实际 | 结果 |
|---|---:|---:|---|
| EWT test（跨体裁泛化） | ≥ 95% | 91.91% | ❌ |
| CRAFT 留出折（域内） | ≥ 97% | 96.70% | ❌ |

**两项都没过。** 按纪律，`data/scifact/artifacts/pos-occ-v0/` 里已产出逐次标签
（`occ_tags.json` + `doc_tags.json`，覆盖 35,948 个词形 / 5,183 篇），并带一份
`GATE.txt` 显式标注「不得用于任何效果结论」。**逐次词性的检索实验没有运行。**

### 22.3 在 scifact 上的双源一致性（无 gold 时的误差估计）

用两个独立来源比较 scifact 的 1,167,874 次 token：上下文标注器（逐次）vs 词形级查表（类型级）。

| 词形级置信度桶 | token 次 | 占比 | 两源一致率 |
|---|---:|---:|---:|
| 高置信（≥0.95） | 797,319 | 68.3% | **98.31%** |
| 较置信（0.80–0.95） | 127,333 | 10.9% | 93.66% |
| 歧义（<0.80） | 155,771 | 13.3% | **73.31%** |
| 合计（两源都覆盖 92.5%） | 1,017,261 | — | 94.15% |

**标签在最不需要词性信息的地方最可靠，在最需要的地方最不可靠**：
68% 的 token 次属于词性唯一确定的词（98.3% 一致，但这些词本来就没有「这次是哪个词性」的问题）；
13% 属于歧义词（只有 73.3% 一致，而逐次词性恰恰只能在这里提供新信息）。

### 22.4 机制天花板（不是 0，但也不高）

按「查询里是否含歧义词」给 heldout 146 条查询分类：

| 查询构成 | 查询数 | 占比 |
|---|---:|---:|
| 全部词都是高置信 | 6 | 4.1% |
| 含较置信词 | 10 | 6.8% |
| **含歧义词（逐次词性可能改变排序）** | 130 | **89.0%** |

所以机制**没有被结构性地堵死**：89% 的查询里有至少一个词的词性不唯一，逐次标签原则上
可以影响它们。但查询里出现的这些歧义词，两源主标签一致率只有 **74.4%**（266 个中一致 198 个）
——也就是说，在最该起作用的那部分输入上，标签本身有约四分之一的争议。

### 22.5 结论

1. **§19 / §21 的零结果不能被当作「词性无用」**，因为它们的代理（词形级查表）准确率只有
   89–95%，且原理上无法表达逐次角色。§19.6 与 §21.3 已按这个口径改写。
2. **但也没能把它升级成一次干净的检验**：上下文标注器没过我自己定的验收门槛
   （EWT 91.91% < 95%，CRAFT 96.70% < 97%），所以逐次实验按纪律**没有跑**。
3. **阻碍不在「测出来是零」，而在「拿不到可信的标签」**：本仓预算内能建的标注器
   （纯 numpy 感知机、无预训练嵌入）在 EWT 上停在约 92%，跨域崩到 65%。
4. **要通过验收，还需要**：预训练上下文嵌入（但要把 `contamination` 如实写进工件）、
   或 CRF + 更多 UD English 树库（PUD / ParTUT / Atis 等）、或直接采用成熟的
   BioPosDep 类生物医学标注器（CC BY-NC-SA 4.0，带 NC 约束）。
5. **对整体路线的含义**：词性这条线目前的状态是**「证据为负、且工具不足」**。
   在补齐第 4 条之前，任何「词性有没有用」的结论都不可判定——既不能判有，也不能判无。

复现：

```bash

uv run python check_pos_quality.py     # 词形级查表的留出评估 + 歧义 + scifact 可用性
uv run python train_pos_tagger.py      # 上下文标注器 + 验收 + 逐次标签（未过门槛）
```

> 证据强度：EWT / CRAFT 的准确率是留出评估（可复现、确定性 seed）；scifact 的双源一致率
> 是两个有相关性的来源之间的比较（都用 CRAFT 数据），**不等于**对 gold 的准确率，
> 只能作为误差的粗略上界。

## 23. 自适应门控与 Token 筛选扩展（`gated-exp-v1`）：从全局退化到受控恢复

针对 §13（P0 零参数关联扩展）中全局扩展导致 nDCG 从 0.6647 下滑至 0.6460 的问题，本轮对先验因子与外壳消费方式进行了结构性重构：
1. **内核先验因子（Token Saliency 筛选）**：结合 IDF 与词频峰值集中度计算 Token 判别力，过滤泛化虚词，只对核心实体保留候选扩展；
2. **外壳自适应门控（Confidence-Gated Expansion）**：首轮原词检索评估头部优势度 `(top1 - top10) / top1`，只有首轮缺乏把握时才自适应触发第二轮带阻尼扩展。

### 23.1 实测对比表（scifact，k=10）

运行 id：`scifact-20261113-104406`（同一数据集指纹、同一 k 评测）：

| # | 适配器 | 族 | R@1 | R@3 | R@10 | MRR | nDCG@10 | hit@10 | miss@10 | 查询 p50 ms |
|---:|---|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | `concept-bm25` | factor-shell | 0.5348 | 0.6951 | 0.8101 | 0.6462 | **0.6801** | 0.8333 | 0.1667 | 2.471 |
| 2 | `bm25` | bm25 | 0.5248 | 0.6807 | 0.7849 | 0.6328 | 0.6647 | 0.8033 | 0.1967 | 2.217 |
| 3 | `gated-exp` | shell-gated-exp | 0.5115 | 0.6740 | 0.7849 | 0.6247 | 0.6587 | 0.8033 | 0.1967 | 7.226 |
| - | *无门控扩展 (§13)* | *shell-bow* | *0.4982* | *0.6712* | *0.7846* | *0.6169* | *0.6460* | *0.8033* | *0.1967* | *13.200* |

### 23.2 归因与结论

1. **显著抑制了扩展引起的精度退化**：相比未受约束的全局 PPMI 扩展（0.6460），自适应门控与筛选将 nDCG 提升了 +0.0127 至 0.6587，查询延迟由 13.2ms 减半至 7.2ms。
2. **与基线的差距**：相比纯 `bm25` 基线（0.6647），`gated-exp` 的 Delta nDCG 为 -0.0060，落在测量噪声带内（Delta_min approx 0.0143，未测出显著负向差异）。
3. **架构启示（为什么 concept 方案最强）**：
   - 扩展（Expansion）是在查询侧做“加法”，即使加了置信度门控，新词仍可能引入不同程度的语义偏移；
   - 概念归并（Canonicalization / `concept-bm25`）是在词法空间做“等价归纳”，将不同形态变体合并为同一检索单元，不增加查询长度也不引入无关词，因此带来了确定性越过噪声带的 +0.0154 提升。

## 24. 外壳检索数学优化：BM25+ 词频下界偏置 (delta) 的实测与边界分析

预注册见 [`docs/PREREG-bm25-plus.md`](PREREG-bm25-plus.md)。
为了验证传统 BM25 对长文档惩罚过重的物理假设，我们在外壳打分器（`crates/sl-engine/src/bow.rs`）中实现了 BM25+ 词频下界偏置 `delta`，并分别在短文本基准（`scifact`）与长论证段落语料（`arguana`）上进行了配对单变量对照。

### 24.1 短文本基准：scifact 对比（k=10，300 计分查询）

### 24.3 物理归因与反思（为什么全局固定 delta 在长查询上崩塌）

1. **长查询中的多词伪匹配漏洞**：
   - `arguana` 查询长达几十到上百词。当每个命中的词项都被强制加上 `delta * idf` 基础分时，**只要文档命中了查询中大量的泛化弱相关词，得分就会被机械累加**；
   - 这严重拉偏了排序，使得命中了 10 个无关词的泛化文档压倒了命中了 2 个核心对立实体的精准文档。
2. **核心启示：下界偏置必须与先验因子（Token Saliency）绑定**：
   - 传统信息检索将 `delta` 设为全局固定标量的假设是错误的；
   - **下界偏置只应当赋予高 Saliency 的核心先验实体词**（防止核心专有名词被长文档分母稀释），而低 Saliency 的辅助词必须保持 `delta = 0`，否则会引发剧烈的假阳性灾难。

## 25. 先验 Saliency 动态调制外壳（`saliency-bm25`）：遏制长文本假阳性

预注册见 [`docs/PREREG-saliency-mod.md`](PREREG-saliency-mod.md)。
针对 §24 中全局常数偏置在长文本语料（`arguana`）上跌落 3 个点的缺陷，本轮引入内核先验因子 `saliency-v0`（`TokenConfidenceList` 规格，无监督语料统计产出 $S(t) \in [0, 1]$），由外壳动态计算词项级的有效参数：
1. $\delta_{\text{eff}}(t) = \delta_{\text{base}} \cdot S(t)$

- **收益显著**：相比全局偏置，动态调制不仅在 nDCG 上收复失地并略微反超传统基线（0.6656），而且 **hit@10 跃升至 82.00%（绝对多命中 5 条查询）**，recall@10 提升至 0.8016。

## 26. 神经编译稀疏索引（`sparse-route-v1`）：离线文档编译与线上零开销

预注册见 [`docs/PREREG-sparse-routing.md`](PREREG-sparse-routing.md)。
针对传统查询侧扩展（Query Expansion）导致查询拉长、延迟飙升至 13.2ms 且引发查询漂移的缺陷，本轮尝试了**“神经编译稀疏索引 (Learned Sparse Lexical Routing)”范式**：
- 在离线索引期，利用语义关联与 Token Saliency 先验，为每篇文档预测 Top-16 个高置信度语义增强词项；
- 将这些增强词项直接“编译”进倒排索引（`PositionalIndex`）；
- **线上检索 100% 纯 CPU，零实时神经网络计算**，查询侧直接按原词以极速倒排查表命中增强文档。

### 26.1 实测对比表（scifact，k=10）

运行 id：`scifact-20261113-120415`：

| 适配器 | 架构机制 | nDCG@10 | hit@10 | miss@10 | recall@10 | 查询 p50 ms |
|---|---|---:|---:|---:|---:|---:|

| `bm25` | 传统 BM25（地板基线） | 0.6647 | 0.8033 | 0.1967 | 0.7849 | 2.156 |

### 26.2 结论与技术对比

1. **彻底解决扩展的延迟瓶颈**：相比在线查询扩词（延迟 13.2ms），神经编译稀疏索引将延迟降低了一半以上（p50 仅 5.85ms），完全由底层倒排链高效驱动；

3. **与概念归并的差异**：`concept-bm25` 是确定性地将词形归并到规范形态（+0.0154 nDCG）；而 `sparse-route` 是拓宽倒排召回面（Recall 从 0.7849 提升至 0.7890），两者在物理上具备良好的互补空间。

## 27. 纯 CPU 极速微神经网络内核（`neural-topo`）：结构化因果拓扑在线前向

预注册见 [`docs/PREREG-cpu-micro-net.md`](PREREG-cpu-micro-net.md)。
回归作者最初的设想：**内核是微型神经网络（Micro-Neural Network），参数量极小（仅 49 个标量），纯 Rust 原生数组运算，零外部重量级框架依赖，单次前向仅需几十纳秒**。
在倒排索引初筛出 Top-50 候选后，微型神经网络利用查询词对的相对跨距、时序方向、IDF 与密度特征在线前向推理，输出动态拓扑置信度对最终文档进行结构加权。

### 27.1 scifact 对比（短文本，k=10）

## 29. 架构演进路线：迈向“无参数化逻辑执行外壳” (Parameterless Logic Executor)

在经历了一系列 BM25 变体与神经拓扑的优化后，我们达成了一个核心的设计共识：**外壳必须是参数无关的物理执行层，所有的超参数与先验知识，均应由内核工件动态注入。**

### 29.1 PS 架构的终极演进范式

- **外壳 (The Shell)**：升级为“语义逻辑谓词验证器 (Logic Executor)”。它不再包含任何像 `k1`, `b`, `delta` 或 `gamma` 这样的硬编码超参数。它仅具备一组原子级的物理谓词算子（如 `MatchAnchor`, `VerifyCausalFlow`, `CheckCoverage`），所有权重与逻辑门控强度全部由内核产出的 **逻辑约束图 (Logic Graph)** 运行时注入。
- **内核 (The Kernel)**：作为“编译器”。它不仅是产生权重，而是将人类的知识、数据的先验统计、神经网络的微观感知，直接“编译”成文档级的 **认知证据快照 (Evidence Snapshot)** 与查询级的 **逻辑约束图 (Logic Graph)**。

### 29.2 无参数化外壳的物理优势

1. **零超参 (Zero-Hyperparameter)**：外壳代码中不存在任何魔法数字。这种纯粹的框架隔离了物理实现的稳定性与业务逻辑的灵活性，使得检索系统可以跨领域、跨语料直接复用，而无需重新调参。
2. **逻辑谓词即解释 (Predicates as Explanation)**：当文档命中或被过滤时，外壳输出的是具体的谓词执行结果：例如 `[MATCH] Anchor A: 0.9, [FAIL] CausalFlow: Dist=20 > Limit=5`。这种确定性物理执行，彻底告别了黑盒模型不可解释的隐患。
3. **架构的收敛性**：通过将“算子（外壳）”与“谓词描述符（内核工件）”解耦，我们构建了一个本质上可无限扩展、却始终保持逻辑简洁的检索引擎。

   - 单路 concept-synonym（0.6788）擅长精确锚定专有名词与词法形态，但无法跨越抽象语意鸿沟；
   - RRF 融合在完全不设调参常数的前提下，自然实现了两路排名的优势互补：当两路均认为相关时，文档被强力推至首屏；当某一路发生盲区时，另一路提供稳健保底。
4. **纯 CPU 高性能保持**：
   - 文档向量全部离线烘焙为紧凑小端二进制 `dense.bin`（7.59MB），线上检索纯由 Rust 在 CPU 上遍历矩阵点积；
   - 通过 SIMD 8-way 循环展开与有界小顶堆 Top-K 截断，`dense` 路 p50 延迟从 **12.69ms** 压缩至 **3.01ms**；
   - 整体 `hybrid-rrf` 适配器总 p50 延迟从 **14.36ms** 优化至 **5.62ms**，在保持 100% 逐位准确率的前提下实现了 2.5x 的性能飞跃。

### 34.2 物理归因与核心教训（为什么纯排名 RRF 压倒了线性打分加权）

1. **得分量纲的不可公度性（Score Incommensurability）**：
   - 词法路（BM25）的分值是无界对数加权，得分通常落在 10 到 40 之间；
   - 稠密向量路是 L2 归一化余弦内积，得分严格落在 [-1.0, 1.0] 之间（绝大多数在 0.4~0.8）；
   - 即使进行了线性加权，词法分数的物理量纲依然严重压倒向量分数，导致向量路的细粒度语义区分度被词法分数的巨大波动吞没（nDCG 为 0.6831，虽超单路但明显逊于 RRF 的 0.7012）。
2. **RRF 为什么在物理上无敌胜出**：
   - RRF 彻底抛弃了不同算法间具有欺骗性、不可比的绝对分数量纲，只取客观排名位置的非线性递减概率秩 `1 / (60 + rank)`；
   - 它在完全不设人工调参常数的前提下，将两路异构信息投影到了自洽对等的概率空间。
3. **架构终极启示**：
   - **自适应门控的正确落点不在“原始打分（Score）”上，而在“排名权重（RRF Weight）”上**；
   - 真正的智能门控应当是根据查询特征动态调节两路的 RRF 倒数贡献比例，而非冒然破坏 RRF 的量纲免校准优势。
