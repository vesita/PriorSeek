## 8. seq 内核 v0（token 时序相关度，MVP）

> 内核第一版，范围按 2026-11-09 定的 MVP：**只做 token 化 + 时序相关性**，深度学习先不铺开。
> 内核工件（`tools/kernel/build_seq.py`）提供词表 / idf / token 间有序转移权（order=1 相邻、order=2 隔一，PPMI）；
> 外壳（`crates/sl-adapters/src/seq.rs`）把 BM25 基本分与「时序分」融合：
> `score = s_uni + λ_seq · Σ e(a,b)·(1+ln(c))`（详见 KERNEL.md §8）。

### 8.2 消融（scifact，λ=0.5 为默认；括号里是相对 bm25 的 ΔnDCG@10）

| 变体 | nDCG@10 | 读法 |
|---|---:|---|
| `bm25`（无时序分） | 0.6647 | 基线 |

| `seq` λ=0.05 | 0.6641 | — |
| `seq` λ=0.1 | 0.6655 | +0.0008（单次运行，不能读成增益） |
| `seq` λ=0.3 | 0.6599 | 开始变差 |
| `seq` λ=0.5（默认） | 0.6515 | −0.0132 |
| `seq` ordered=false | 0.6509 | 比有序还差 → 顺序本身有微弱信息 |
| `seq` orders=[1] | 0.6583 | 只用相邻阶比 [1,2] 好 → 隔一阶带来了噪声 |
| `seq` window=4 | 0.6523 | — |
| `seq` window=16 | 0.6470 | 窗口越大越差 → 距离越远越不该加分 |

### 8.3 怎么读（结论与边界）

1. **统计版时序分目前没有增益**：四个数据集上 λ=0.5 都比同口径 `bm25` 低；λ=0.1 在 scifact 上只高 +0.0008（单次运行，
   谈不上增益）。这与预期一致：PPMI 是「共现统计」，不是「学到的相关度先验」，它把大量弱相关邻接当成证据，
   在短文档/短查询上主要制造噪声。
2. **但结构与工具链已经成立**：工件格式、哈希审计、CPU 运行时、Python↔Rust 逐位对拍（见 8.4）、
   λ/窗口/阶数/有序性的消融开关全部就位——后续换「学习到的权重」只换工件，不动外壳与指标。
3. **消融给出的方向（供学习版参考）**：顺序（ordered）与近邻（order=1、窗口 ≤8）有微弱正信息；
   隔一阶与大窗口引入噪声。学习版应该只在这些有信息的边上学习权重，而不是全量 PPMI 边。
4. 证据强度：每格**单次运行**；延迟在同一台机器（有 GPU，但运行时强制 CPU）测得，rs 等外部对比不可与本章混读。

- 工件（`data/<name>/artifacts/seq-v0/`）登记在 run.json：`seq_graph / corpus_ppmi / runtime=cpu`，

## 9. M2-lite：学 2 个时序权重（kernel v1）—— 预注册口径作废，但测出关键分辨率

预注册与全部读数见 [`docs/PREREG-M2.md`](PREREG-M2.md)。这里只记结论。

### 9.1 结果

| 项 | 值 |
|---|---|
| 训练数据 | scifact train split：809 条查询 / 919 条正例（新增 `train_queries.jsonl` + `train_qrels.tsv`，**不进 manifest 指纹**） |
| 学习参数 | **2 个**（`a1`、`a2`；`λ` 与阶权重之间只有一个尺度自由度） |
| 预注册口径结果 | `a1 = a2 = 0`（边界解），代理损失 400 步不动，top-10 变化 **0%** |
| 按预注册纪律 | N4（非零性冒烟 ≥10%）**未过** ⇒ 该变体**作废**，不出「有效/无效」结论 |
| test | **未跑**：a=0 ⇒ `seq` 与 `bm25` 逐位相同（N1 已证），Δ 恒为 0 |

### 9.2 诊断：不是「特征没信号」，是「集成方式与代理饱和」

| 逐查询 AUC（正例 vs 同查询候选负例） | s_uni 0.972 | s1（order=1）**0.791** | s2（order=2）0.631 |
|---|---|---|---|

- `a=0` 处 `dL/da1 = +0.0046 > 0` ⇒ 非负约束下最优就在 0，不是优化没跑够；
- 分数未归一（均值 `|du|` = 27.9），pairwise logistic 饱和到 sigmoid ≈ 0 ⇒ 梯度近乎为 0；
- 归一化后权重能动了（探索性变体：best train ΔnDCG@10 = **+0.0006**），但仍远小于可判定阈值。

结论：**时序特征本身有信息（AUC 0.79），但以「加性 bonus 叠在 BM25 上」的方式在 2 参数下学不出增益**；
瓶颈在集成方式与测量分辨率，不在参数数量。

### 9.3 一个影响所有旧结论的校准：scifact test 只能分辨 0.0143

用同一轮配对结果（`results/scifact-20261109-181810-seq-fixed`）做 4000 次配对 bootstrap：

```text
300 条计分查询 → ΔnDCG@10 的 bootstrap SE = 0.00716
Δ_min = 2×SE = 0.0143
```

⇒ **scifact test 上只有 |Δ| ≥ 0.0143 才可判定**。因此 §8.2 消融表里的所有差异
（0.0008 / 0.005 / 0.013，包括「λ=0.5 比 bm25 差 0.0132」）**全部落在噪声带内**：
「λ 越大越差」「order=2 是噪声」「ordered 优于 unordered」这些方向性说法在 scifact 上**都还不成立**，
只能写「该口径下未测出差异」。§8.2 的表格保留为原始读数，但读法以本节为准。

> 这条校准来自 flowme 的 Δ_min 纪律（`docs/REFERENCE_NOTES.md` §2）：**没测出差异 ≠ 没有效果**。
> 后续所有小效应实验必须先看目标数据集的 Δ_min，再决定值不值得做。

## 10. M2b：以搜索缺失率为目标（精确网格，无代理损失）

完整记录见 [`docs/PREREG-M2b.md`](PREREG-M2b.md)。这里只记结论与它对路线的含义。

### 10.1 先把「缺失率」变成一等指标

`sl-core` 新增 `Metrics.hit`（`hit@k` = top-k 里至少命中一条相关文档的查询占比），报告里新增
「查询命中率 / 缺失率」表。它和 recall 的口径不同，不能混读：

| 场景 | recall@10 | hit@10 |
|---|---:|---:|
| 一条查询有 5 篇相关，只召回 1 篇 | 0.2 | **1**（没漏） |

`docs/STANDARD.md` §5 已补该定义，含「hit/miss 报 Δ 时必须给 Δ_min」的纪律。

### 10.2 scifact 上的缺失率现状（bm25，300 条计分查询）

| 指标 | 值 |
|---|---:|
| miss@10 | **19.67%**（59 条查询第一屏一条都没命中） |
| miss@100 | 10.33%（31 条） |
| 其中 11–100 名（重排可救） | **9.3%**（28 条） |
| 其中 top-100 完全没有相关（打分救不了） | **10.3%**（31 条） |
| 完美重排的 hit@10 上限 | 0.8967（现状 0.8033） |

### 10.3 结果：直接优化缺失率，仍然零增益

| 阶段 | 读数 |
|---|---|
| train 网格搜索（1402 点，含负值扩展 225 点） | 最优 `(a1=0, a2=0.2)`，hit@10 0.8140 → 0.8152，**只多命中 1 条查询** |
| test（只跑一次） | hit@10 **0.8033 → 0.8033（Δ=0.0000，0 条查询变化）**；hit@100 −0.0033 < Δ_min 0.0067 |

- 换目标（排序代理 → 业务缺失率）、换优化方式（梯度 → 精确穷举）、换样本（train 809 条）
  **都指向同一答案**：2 个加性时序权重对「能不能命中」没有作用。
- 原因：命中由**前 10 名边界**决定，而加性时序奖励对所有含查询词项的文档普遍加分，
  基本不改变候选相对次序——它不能把第 30 名推上前 10。

### 10.4 对路线的含义（重要）

「搜索缺失率」这个目标是对的，但它指向的**不是**时序权重，而是两个别的模块：

| 缺失类型 | 占比 | 需要的机制 | 属不属于当前内核 |
|---|---:|---|---|
| 首个相关在 11–100 名（重排可救） | 9.3% | 能区分近邻候选的信号（cross-encoder / query-doc 交互分 / 更强的学习表示） | ❌ 超出「2 个时序权重」 |
| top-100 完全无相关（词汇不匹配） | 10.3% | 查询扩展、同义/缩写归一、更好的表示 | ❌ 属于召回/表示层 |

⇒ MVP 阶段「token 化 + 时序相关性」这条内核路线到此有了明确边界：**它能做的是排序细分，
做不到救漏**。要继续降低缺失率，得进入重排或表示层——那已超出「内核只学时序特征」的范围，
需按 `docs/STANDARD.md` §8 重新排期。

## 11. 换 LLM tokenizer（`bm25-llm`）—— 单变量对照：**纯词法上更差**

动机：词级切分丢掉形态学（`monocyte` ≠ `monocytes`）。实测「硬漏」查询的相关文档词级覆盖率只有
0.323，而字符 3-gram 能到 0.604 ⇒ 子词信息确实存在。按「不自己造」的原则，直接用成熟 LLM 的 BPE。

### 11.1 设置

| 项 | 值 |
|---|---|
| tokenizer | Qwen2.5-0.5B `tokenizer.json`，BPE，151,665 词表，sha256 `c0382117…` |
| 对照组 | `bm25`（词级切分，`tokenize::bm25_terms`） |
| 唯一变量 | **tokenizer**；k1=1.5 / b=0.75 / 同分排序 / 过滤规则完全相同 |
| 数据 | scifact，同一指纹 `7bf0074d…`，k=100，warmup=3 |

### 11.2 结果

| 指标 | `bm25`（词级） | `bm25-llm`（BPE） | Δ |
|---|---:|---:|---:|
| nDCG@10 | **0.6647** | 0.6350 | −0.0297 |
| MRR@10 | **0.6328** | 0.6006 | −0.0322 |
| R@10 | **0.7849** | 0.7644 | −0.0205 |
| R@100 | 0.8892 | 0.8927 | +0.0035 |
| **miss@10** | **19.67%** | 22.33% | **+2.67pp（更差）** |
| miss@100 | 10.33% | 10.33% | 0 |
| 索引 ms | 186 | 1,613 | 8.7× |
| 查询 p50 ms | 0.21 | 0.44 | 2.1× |

配对 bootstrap（300 条计分查询）：`ΔnDCG@10 = +0.0297`，`SE = 0.0138`，**`Δ_min = 0.0277`**
⇒ 这个差距**刚刚超过可判定阈值**（不是噪声，但幅度不大）。

### 11.3 诊断：为什么更差，以及它救回了什么

- **token 数膨胀 1.46×**（词级 229/文档 → BPE 333/文档），BM25 的 `b` 与词频饱和在不同粒度上标定不同；
- **IDF 被摊薄**：BPE 拆出 `mon`、`ation`、`Ġthe` 这类高频子词，它们在几乎所有文档里出现，
  对排序几乎没有区分度；而 BM25 的全部威力来自「稀有精确词」。
- **但它是互补的**：`hit@10` 上 llm **救回 11 条** bm25 漏掉的查询，同时**弄丢 19 条**，净 −8。
  ⇒ 子词信号真实存在，只是被「高频子词摊薄 IDF」掩盖了。

### 11.4 结论与下一步

**「直接换 LLM tokenizer」这条路单独走不通**（至少在纯词法 BM25 上），但它证明了子词信息有价值。
两条可行的接法（都还没做）：

| 选项 | 思路 | 预期 |
|---|---|---|
| **A. 混合打分** | 词级 BM25 为主 + 子词 BM25 为辅（或只在词级零命中时用子词兜底） | 吃回那 11 条，同时不丢那 19 条 |
| B. 重新标定 b/k1 | BPE 文档更长 ⇒ b 可能需要下调 | 小幅，且要在 train 上调、test 上一次评 |
| C. 交给神经路径 | BPE 本来就是给模型用的：用它做 embedding / cross-encoder 的输入 | 超出当前「词法 + 时序」范围 |

**证据强度：单次运行，但 Δ 刚过 Δ_min**；延迟与索引差异是量级性的，不依赖统计。
