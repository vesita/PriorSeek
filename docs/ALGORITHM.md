# 检索算法：有序对齐覆盖（OAC）

> 本仓的主算法定义与实测结论。口径纪律见 [`STANDARD.md`](STANDARD.md)，
> 内核接口见 [`KERNEL.md`](KERNEL.md)，结果汇总见 [`RESULTS.md`](RESULTS.md) §12。

## 1. 算法定义

把检索定义为「查询词序列在文档中的最优有序对齐」，分数是该对齐上逐项 BM25 权重的和。

```text
q = [t1, ..., tn]        查询词序列（token id）
d = 文档 token 序列

一个对齐 A = {(i, j)}，满足：
    i 严格递增（按查询顺序取词）
    j 严格递增（在文档里位置递增）
    j 与上一个 j 的间隔 ≤ window（允许跨距，但不许无限远）
    允许跳过 ≤ max_skip 个查询词

score(q, d) = max over A  Σ_{(i,j) ∈ A}  w(t_i, d) · K(gap(j, j_prev))

w(t, d) = idf(t) · tf·(k1+1) / (tf + k1·(1−b+b·len_d/avg_len))     ← BM25 的逐项权重
K(g)    = 内核提供的 gap 权重（5 个桶：1 / 2 / 3–4 / 5–8 / >8）
```

三个定义性部件（缺一不可）：

| 部件 | 作用 | 谁提供 |
|---|---|---|
| `w(t,d)` 逐项权重 | 一次匹配值多少分（tf 饱和 + 长度归一） | 外壳（与 BM25 同一份数学） |
| **有序约束** | 哪些匹配可以**同时**计入 | 外壳（本算法的核心） |
| `K(g)` gap 权重 | 跨距多远还值钱 | **先验因子**（内核产出，外壳消费；当前由 `seq-v0` 统计给出） |

## 2. 为什么这算「一套算法」而不是「组合权重」

因为它把经典检索的两个端点**包含为退化情形**，而不是用权重去调和它们：

| 设定 | 退化成 | 实测等价性 |
|---|---|---|
| `ordered = false` | **BM25**（逐字相同） | ✅ **逐位一致**（scifact 300/300 条查询，0 差异） |
| `ordered = true` 且 `K` 只在 gap=1 时为 1 | 短语匹配 | —— |
| 一般情形 | 有序 + 跨距折扣 | 见 §4 |

`ordered = false` 时公式逐字退化成 BM25，这条不只是纸面推导：`bow`（词袋端点）与既有 `bm25`
适配器在 scifact 上 **300 条计分查询逐查询指标完全一致**（等价性门 G1）；
OAC 开 `ordered=false` 时也与 `bm25` **逐位一致**（G1'）。所以 BM25 不是"要被打败的对手"，
而是本算法的一个特例。

## 3. 外壳结构

```text
crates/sl-engine
  PositionalIndex   唯一一份位置索引：doc token 序列 + 倒排位置表 + df/len/idf
                    （不认识 tokenizer：token 以 u32 传入）
  BowScorer         词袋端点（BM25 数学），用于 G1 等价性门与消融对照
  OacScorer         本算法：有序对齐 DP
                    复杂度 O(命中出现数 × max_skip × window)，与文档长度线性、与语料规模无关
  KernelGapTable    先验因子槽位：gap → 权重（5 桶）
                    ↑ 内核与外壳的唯一边界；换内核只换这张表的内容，算法形式不变
```

`crates/sl-adapters/src/shell.rs` 把它接成两个适配器：`bow`（端点）与 `oac`（主算法）。
tokenizer 由 `SL_SHELL_TOKENIZER` 选择（`word` / `qwen`），**换 tokenizer 不换实现**。

### 实现中修掉的两个真 bug

1. **环形缓冲用取模做位置校验**：`window` 容器的索引用 `pos % rows`，当窗口小于实际距离时，
   会把远处的位置错认成近处，产生不该有的对齐转移。改用「(位置, 值) 显式校验 + 前缀最优」。
2. **无序端点概念写错**：最初写成「不要求位置递增、但仍要求查询下标递增」，那仍然带着查询顺序，
   所以反序文档会被系统性压低。真·无序端点应当是**每个查询词独立贡献**（词袋），改后与 BM25 逐位一致。

这两个 bug 由单测抓出（`cargo test -p sl-engine`，11 条）。若没抓住，指标会静默错。

## 4. 实测（scifact，同一指纹 `7bf0074d…`，k=100，warmup=3）

| 配置 | nDCG@10 | MRR@10 | 相对 BM25 |
|---|---:|---:|---:|
| `ordered=false`（= BM25） | **0.6647** | 0.6328 | 基准 |
| 有序 + 无折扣 | 0.5427 | 0.4992 | **−0.1220** |
| 有序 + 衰减核 `1,.8,.6,.4,.2` | 0.5569 | 0.5134 | −0.1078 |
| 有序 + window=4 | 0.5432 | 0.4971 | −0.1215 |
| 有序 + window=16 | 0.5632 | 0.5284 | −0.1015 |
| 有序 + `max_skip=0` | 0.5118 | 0.4545 | −0.1529 |

配对 bootstrap 的 `Δ_min` 在 scifact 上是 **0.0143**（见 `RESULTS.md` §9.3）——
上表所有差异都**远超**它，所以这不是噪声。

## 5. 结论：有序约束在这个任务上**有害**，且原因是结构性的

先给结论，再给原因：

> **在 scifact 上，"查询词必须按序出现"这个约束稳定地损失约 0.10–0.12 nDCG@10，
> 而且调窗口、调内核折扣、调跳过都不改变方向。**

原因是**结构性的，不是参数没调好**：

1. 有序约束在形式上是一个**剪枝**：它只决定"哪些匹配可以同时计入"，永远**只能减少**可计入的证据，
   **不会增加**任何新证据。查询有 8–10 个词、文档按不同顺序提及它们时，单调约束只能取一个子集，
   分数必然低于"全部计入"。
2. 因此要让顺序信息**有用**，它必须带来**加法**（例如相邻匹配额外加分），而不是**减法**。
   而"加性奖励"这条路我们已经单独测过（`PREREG-M2.md` / `PREREG-M2b.md`）：
   train 上 1402 个网格点最多多命中 1 条查询，test 上 0 条查询变化。
3. 两条路都失败，指向同一个事实：**`query token 在文档中的顺序/邻近` 这个信号，
   在本任务上不携带能提升排序的增量信息。**

## 6. 这条结论的边界（不要过度推广）

- 只在 **scifact**（英文科学摘要，短文档）上验证；中文短标题（qbqtc）、长文档（nq-sub）未测。
- 只验证了「BM25 逐项权重 + 有序约束」这一族；**没有**验证学习到的表示（稠密向量）——那是另一个信号源。
- 结论是「这个特征在这个任务上没增益」，不是「顺序信息在任何检索任务上都没用」
  （短语检索在长文档上是有效的，只是本任务的数据形态不吃这一套）。

## 7. 成本

| 项 | `bow`（词袋） | `oac`（有序对齐） |
|---|---:|---:|
| 索引 ms（scifact） | 175–186 | 181–187 |
| 查询 p50 ms | 0.21 | **7.1**（约 33×） |
| 查询 p95 ms | 0.26 | 16.8 |

OAC 慢在「每篇候选文档都要做一次对齐 DP」。当前实现没有做候选裁剪，
若将来要继续这条路，必须先按廉价分取 top-N 候选再做对齐。

## 8. 可复现命令

```bash
cargo build --release -p sl-cli
# 等价性门 G1：bow 必须与 bm25 逐查询一致
./target/release/sl run --dataset scifact --adapters bm25,bow --k 100 --warmup 3 --label g1-equiv
# 等价性门 G1'：OAC 无序端点必须与 bm25 逐位一致

# 主算法 + 消融
./target/release/sl run --dataset scifact --adapters oac --k 100 --warmup 3 --label oac4-ordered

SL_OAC_WINDOW=4 ./target/release/sl run --dataset scifact --adapters oac --k 100 --warmup 3 --label oac4-w4
```

## 9. 神经稀疏带权倒排点积算法（`learned-sparse` & `bilingual-sparse`）

### 9.1 数学形式
传统 BM25 的打分形式依赖启发式饱和曲线与人工超参数：
```text
score_BM25(q, d) = Σ_{t ∈ q ∩ d} idf(t) · [ tf · (k1 + 1) / (tf + k1 · (1 - b + b · len_d / avg_len)) ]
```
其中 `k1` 和 `b` 是经验常数，无法捕捉未字面出现的近义词。

神经稀疏算法将词项权重预测彻底交给深度学习离线内核：
```text
score_Sparse(q, d) = Σ_{t ∈ q ∩ d} w(t, q) · w(t, d)
```
- 每个文档词权重 `w(t, d)` 与查询词权重 `w(t, q)` 均由深度学习网络（SPLADE 架构）端到端学得；
- 模型自动完成了重要度加权、停用词压制、以及未显式出现的上下文同义词扩展；
- **外壳零超参**：不再包含任何人为设定的调节参数；
- 外壳纯 Rust 实现带权倒排索引（`SparseInvertedIndex`），结合有界最小堆完成 Top-K 截断，纯 CPU 运行，查询延迟仅为 **26~28 微秒**。
