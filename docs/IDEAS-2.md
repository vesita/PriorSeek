# 优化方案（第二版）：基于 §1–§54 的实测

> 判据沿用 C1–C3（不拟合融合权重、条件可解释、跨数据集同向）。
> 每条都标注"证据位置 / 代价 / 最小可证伪实验"。

## 1. 稀疏因子本身还有多少空间

§54 的截断扫描说明：因子质量对超参敏感（32 → 128 是 +7.5pp），但 128 → 256 只有 +0.4pp。
顺着这条线，还剩三个可测的旋钮：

| # | 优化 | 机制 | 预期 | 代价 |
|---|---|---|---|---|
| S1 | **标题字段加权** | 建工件时把 title 重复 2 次再编码（或按字段分别编码后相加） | 标题命中是强信号（§14.1 证明字段有信号，当时失败的是 per-token 因子） | 零成本，重建工件即可 |
| S2 | **int8 量化** | 文档权重线性量化到 8bit，点积用整数累加 | 体积 −75%，延迟下降 | 中（改索引格式与内核） |
| S3 | **索引期剪枝** | 按权重阈值裁掉低贡献 postings（当前阈值 0.05 已经是剪枝） | 体积/延迟 | 低（扫阈值即可） |

## 2. 跨语言的另一条路：语料侧翻译

已知（§48 §50–§53）：**查询侧翻译**损失 12–21pp；词典/关键词路线全部更差。
未试的是反方向：**把语料翻成目标语言，索引两份，各自用本语种模型**。

| 维度 | 查询侧翻译（已测） | 语料侧翻译（待测） |
|---|---|---|
| 翻译对象 | 短查询，歧义大 | 长文档，上下文充分 |
| 索引成本 | 1 份 | 2 份 |
| 查询成本 | 每条查询一次翻译 | 零（直接命中本语种索引） |
| 已验证 | 稀疏 0.5438 | — |

最小实验：把 scifact 语料译成中文 → 用 SPLADE-zh 建工件 → 原中文查询直接检索（同一 qrels）。
判据：若 > 0.5438，说明"语料侧翻译"优于"查询侧翻译"，跨语言主线应改为双索引。

## 3. 分数校准与因子融合（谨慎）

现状：稀疏（0.6985）单独最强；BM25（0.6647）地板。
两者候选集合不同（§33：RRF 融合收益来自差异路），但稀疏已包含 BM25 的多数信息。

可测的最小方案：**候选并集 + 单一打分器**——用 BM25 补召回（稀疏未召回的文档），
最终排序仍只用稀疏分；这不需要融合权重（C1 允许）。

## 4. 语料适用性诊断（把"为什么不迁移"变成规则）

已有四个数据集的因子增益（§38 §41 §45 §46）与语料统计：
形态变体率、OOV 率、文档长度中位数、查询长度。目标：产出一张"语料 → 推荐因子"表，
让"某因子在某语料无效"从事故变成可预测结论。零训练成本。

## 5. 蒸馏（暂缓）

§49 证明向量 KL 只能到 0.3775；正确做法是 listwise 排序损失 + 更大容量。
但它回答的是"能不能不用 109M 模型"，不改变当前主线的效果上限，故排在最后。

## 优先级

| 顺序 | 方案 | 为什么先做 |
|---|---|---|
| 1 | **S1 标题加权** | 零成本，重建工件即可，直接检验"字段因子对稀疏也有效" |
| 2 | **语料侧翻译** | 唯一还没试过的跨语言方向，可能把 0.5438 往上推 |
| 3 | S3 剪枝阈值扫描 | 工程收益明确，顺带验证"因子冗余度" |
| 4 | 候选并集（BM25 补召回） | 便宜，检验稀疏是否漏召回 |
| 5 | 语料诊断 | 把已有结论固化成规则 |
| 6 | S2 量化 / 蒸馏 | 工程与训练，放最后 |

## 不做

- 不再加几何/顺序类因子（§12 §38 §44）；
- 不再用通用词典做跨语言（§50 §53）；
- 不再拟合融合权重（C1）。
